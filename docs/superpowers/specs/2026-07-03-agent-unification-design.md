# Unified agent instructions & skills — design

Date: 2026-07-03
Status: approved (approach A + project-level symlink convention)
Session: agent_joinage

## Goal

One source of truth for the instruction `.md` files and skills used by every
coding agent on this machine — **Claude Code, Codex CLI, Pi, and omp** — with
per-agent deltas kept small and explicit, and a repeatable convention for
per-project files.

## Current state (why)

- Shared guidance is duplicated and diverging: the psudo/sudo workflow is
  written 3 times (`~/CLAUDE.md`, `~/src/pagent/home/AGENTS.md`,
  `~/.claude/CLAUDE.md`), serve-report guidance 4 times.
- `serving-reports` skill exists as two diverged copies
  (`~/.claude/skills/serving-reports` vs `~/src/agents/pi/skills/serving-reports`
  — the Pi copy has a `scripts/` dir the Claude copy lacks).
- Two repos share the mandate: `~/src/pagent` (infra scripts + canonical
  `~/AGENTS.md` symlink) and `~/src/agents` (per-agent resources).
- `~/.codex/AGENTS.md` and `~/.config/pi/AGENTS.md` are near-identical files
  maintained by a third mechanism (fetcher plugin managed blocks).

## Verified constraints

- **Claude Code does not read AGENTS.md** at any scope. Official memory docs:
  "Claude Code reads `CLAUDE.md`, not `AGENTS.md`. If your repository already
  uses `AGENTS.md` for other coding agents, create a `CLAUDE.md` that imports
  it…" — both `@AGENTS.md` import and symlink are documented options.
- **Codex** reads `~/.codex/AGENTS.md` (user) + repo `AGENTS.md`; skills from
  `~/.codex/skills/` and `.codex/skills/`. No include syntax.
- **Pi** reads `~/.config/pi/AGENTS.md` (user) + repo `AGENTS.md`.
- **omp** loads context files through a provider registry (own `.omp` dirs,
  `~/.codex/AGENTS.md`, `.claude/` CLAUDE.md, GEMINI.md, opencode, Copilot…)
  and **dedupes per level by provider priority** (key: `user` or
  `project:<depth>`), so it will not double-load a symlinked
  CLAUDE.md/AGENTS.md pair. Skills discovered from `~/.omp/agent/skills`,
  `.omp/skills`, `~/.codex/skills`, `.claude/skills`, and Claude plugins.
- All four agents consume the same `SKILL.md` format.

## Design

### 1. Source repo layout (`~/src/agents`)

```
shared/
  AGENTS.md            # unified core instructions (single source of truth)
  skills/              # canonical copy of each shared skill
    serving-reports/
    crisp-writing/
home/
  AGENTS.md            # home-dir-specific notes only (NOT the core)
claude/local.md        # per-agent deltas; existing claude/commands/ stays
codex/local.md
pi/local.md            # existing pi/skills (pi-only), pi/extensions stay
omp/local.md           # existing omp/extensions reference stays
bin/agents-sync        # installer: sync | check | diff
docs/superpowers/specs/  # this doc; plans alongside
```

`~/src/pagent` keeps only infrastructure (psudo, dispatch server, tester glue,
git hooks). Its `home/AGENTS.md` content migrates into `shared/AGENTS.md`;
the file itself becomes a pointer or is retired once `~/AGENTS.md` is
repointed.

### 2. Generation (`agents-sync`)

Each agent's **global** file is generated as: banner + `shared/AGENTS.md` +
`<agent>/local.md`.

| Target | Composition |
|---|---|
| `~/.claude/CLAUDE.md` | shared + claude/local.md |
| `~/.codex/AGENTS.md` | shared + codex/local.md |
| `~/.config/pi/AGENTS.md` | shared + pi/local.md |
| `~/.omp/agent/AGENTS.md` | shared + omp/local.md |

Rules:
- Banner: `<!-- GENERATED by agents-sync — edit ~/src/agents/..., then run agents-sync -->`.
- **Foreign managed blocks are preserved**: any `<!-- name:begin -->…<!-- name:end -->`
  region present in the existing target (e.g. the fetcher plugin's block) is
  re-emitted verbatim after the generated content, so other installers keep
  working. `agents-sync` never writes inside foreign blocks.
- `agents-sync check` regenerates in-memory and exits non-zero on drift
  (listing drifted files); `agents-sync diff` shows the diffs. `check` runs in
  the agents repo pre-commit hook.
- Idempotent: running `sync` twice produces no changes.

### 3. Content split (avoiding double-loading)

Claude Code and omp walk up from cwd and load `~/CLAUDE.md` / `~/AGENTS.md`
*in addition to* their user-level global file. Therefore:

- **Shared core lives only in the generated per-agent globals.**
- `~/AGENTS.md` is repointed: symlink → `~/src/agents/home/AGENTS.md`, which
  shrinks to genuinely home-specific content (local GitLab coordinates, etc.).
- `~/CLAUDE.md` becomes a symlink → `~/AGENTS.md` (first application of the
  project convention). Its current content (psudo, shell aliases) migrates
  into `shared/AGENTS.md`.
- `<agent>/local.md` holds only true per-agent deltas: Claude's
  subagent-model routing and usage-limit checkpointing, Codex-specific notes,
  Pi's `request_sudo_handoff` variant, omp specifics. The shared core states
  the generic rule; local.md states the agent's mechanism.

### 4. Skills

- `shared/skills/<name>/` is the canonical copy. `agents-sync` maintains
  **per-skill symlinks** into `~/.claude/skills/`, `~/.codex/skills/`, and
  `~/.omp/agent/skills/`; Pi discovers skills from the repo path it already
  uses (`~/src/agents/pi/skills`) — shared skills get symlinks there too.
- Reconciliation: `serving-reports` — take the Pi copy (superset, has
  `scripts/`) as canonical, fold in any Claude-copy deltas, move to
  `shared/skills/`. `crisp-writing` moves from `~/.claude/skills/` to
  `shared/skills/` (all agents benefit).
- Per-agent skills stay put: `slice-for-ender3` remains a project-repo symlink
  in `~/.claude/skills/` (or is added to shared later); Pi-only skills stay in
  `pi/skills/`. omp `managed-skills` (auto-learned) are untouched.
- Ownership rule: `agents-sync` only creates/removes symlinks **that point
  into `~/src/agents`**; it never deletes real directories or foreign links.
- Claude Code plugins (superpowers, codex plugin, …) are out of scope —
  Claude-only ecosystem, already managed by the plugin system. omp reads
  Claude plugin skills natively on its own.

### 5. Per-project convention

For any repo: **`AGENTS.md` is the file you write**; `CLAUDE.md` is a relative
symlink to it (`ln -s AGENTS.md CLAUDE.md`) — sanctioned by Claude Code docs;
Codex/Pi/omp read `AGENTS.md` natively and omp's per-depth dedupe prevents
double-load. `NOTES.md` (per the existing convention) holds accumulated local
facts, not instructions. `.worktrees/` stays gitignored. Existing repos
migrate opportunistically — when an agent next touches a repo's CLAUDE.md, it
converts it. Optionally later: a tiny `agents-init` helper scaffolding
AGENTS.md + symlink + .gitignore entries in a new repo (not in v1).

### 6. Migration

1. Build `shared/AGENTS.md` by merging, deduplicating, and reconciling:
   `~/src/pagent/home/AGENTS.md` + `~/.claude/CLAUDE.md` + `~/CLAUDE.md`.
   Conflicts resolve to the most recently updated guidance; the psudo
   workflow keeps the generic core + per-agent mechanisms in local.md files.
2. Populate `<agent>/local.md` with the agent-specific residue.
3. Move/reconcile skills into `shared/skills/` (serving-reports, crisp-writing).
4. Implement `bin/agents-sync`; run it; verify targets.
5. Repoint `~/AGENTS.md` → `~/src/agents/home/AGENTS.md`; replace `~/CLAUDE.md`
   with symlink → `~/AGENTS.md`. (Old files are git-tracked or trashed via
   trash-put, so recoverable.)
6. Slim `~/src/pagent/home/AGENTS.md` to a pointer at the new home; commit
   both repos.
7. The dotfiles/fetcher installer keeps managing its own block inside the
   generated files (preserved region).

### 7. Verification

- `agents-sync sync` twice → second run reports no changes; `check` passes.
- Each agent, non-interactively, is asked what standing instructions it sees:
  `claude -p`, `codex exec`, `pi -p`, `omp -p` with a probe question (e.g.
  "what is the psudo workflow?" and "which skills do you see?"). Each must
  reflect the shared core + its own deltas, without duplication.
- Skills: verify each agent lists `serving-reports` and can read its SKILL.md
  through the symlink.
- Drift: hand-edit a generated file → `agents-sync check` fails → `sync`
  repairs.

## Out of scope

- Claude Code plugins/marketplaces; omp managed-skills.
- `~/src/pagent` scripts (unchanged, still the infra home).
- Bulk migration of every repo under `~/src` (convention applies
  opportunistically).
- Windows/portability concerns; this is a single-machine setup.

## Risks & mitigations

- **Stale generated files after editing source** → banner instruction +
  `check` in pre-commit + a line in the shared core telling agents to edit
  source and re-run sync.
- **An agent updates its own global file in place** (e.g. Claude `/memory`,
  `#` shortcuts append to `~/.claude/CLAUDE.md`) → those edits land in the
  generated file and would be flagged/lost; the shared core instructs agents
  (and the user is warned) to make durable edits in `~/src/agents`. `check`
  surfaces accidental appends before they're clobbered; `sync` refuses to
  overwrite a drifted target unless `--force` (or after showing the diff)
  so hand-edits are never silently lost.
- **omp provider priority surprises** (which user-level file wins) → verified
  empirically in step 7 probes.
