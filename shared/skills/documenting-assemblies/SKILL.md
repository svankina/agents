# Document an assembly

A mechanism is not delivered until it has three things, all from one spec:

- an assembly manual webpage with Voron-style step drawings,
- an interactive assembly animation that the user can pause, scrub, orbit,
  pan, and zoom,
- a clearance certificate for every assembly motion.

`assembly-docs` builds all three. Do not hand-write manual pages, renderers,
or players for one project. If the library lacks something, extend it (see
Extending) so the next mechanism gets the improvement.

## Procedure

1. **Export the model.** Export one labelled `Solid` per instance from one
   `Compound`, to STEP and to GLB (`unit=Unit.M`). Label instances
   `<type>_<n>`. Repeated instances share a type and are counted as one part.
   Do not end a type in a numeric group: `bearing_608zz_1`, not
   `bearing_608_1`. Build repeated parts with `copy.deepcopy`, because
   instances that share geometry keep only one label. Follow
   `templates/example/mechanism.py`.
2. **Write `assembly.json`.** Start from `templates/example/assembly.json`;
   `assembly-docs --help` gives the full format. Order the steps the way a
   person builds the mechanism:
   - One step is one action: one part kind, or one kind of fastener.
   - Start each move clear of every fitted part. Approach along the real
     insertion axis. Add waypoints when a part must go around something.
   - Every instance is introduced once, by `place` or by a move. Keep
     subassemblies that travel together in one move.
   - Set a step `view` that shows the new parts; `build` warns when a labelled
     part is hidden. Use `focus` to zoom into a region of a large assembly.
   - Write notes in ASD-STE100: short sentences, one instruction per sentence,
     active voice. Use `tip` and `warning` kinds where they apply.
   - Thread engagement, press fits, and other nominal overlaps need an
     `allowed` pair with the physical reason. Never allow an overlap to hide a
     defect.
3. **Check.** Run `fair-run -- assembly-docs check assembly.json`. A FAIL
   on a move means the sequence or path is wrong: change it. A FAIL in the
   assembled state is a design defect: fix the model.
4. **Publish.** Run `assembly-docs publish assembly.json`. It prints one URL:
   the manual at `/` and the animation at `/animation.html`. Give the user the
   URL. Also deliver the model through `serving-cad-files` when the model
   itself is the subject.
5. **Inspect.** Open the manual in the browser tool at desktop and phone
   widths and look at every step. Confirm that each label points at the right
   part and that new parts are visible. Open the animation; play, pause,
   scrub, and pan it. Report what you inspected.

`build` and `publish` refuse a missing, failed, or stale certificate. Use
`--draft` only for work in progress; draft output says so in the manual header.

## What the library does

- **check** imports the STEP. For each move it tests the moving parts against
  every part fitted before them. It samples the exact BREP distance and
  advances by at least the current clearance. No pose between samples can
  penetrate deeper than `tolerance_mm` (default 0.05 mm). It also checks every
  pair in the assembled state. Motions are translations only, so the check
  covers the whole path. It uses nominal geometry; it does not prove fit,
  tolerance stack-up, strength, or print accuracy.
- **build** renders the figures in headless Chromium with Playwright. The
  manual is a responsive webpage with no cover or front matter: a step list
  beside large step figures on wide screens, stacked on phones, and a parts
  list at the end. Step figures are white line art. Parts added in the step
  are blue, with guide lines along their paths and labelled pills. The
  animation uses the same timeline, so the two never disagree.
- The animation supports play/pause (Space), step navigation (arrow keys),
  scrubbing, speed, loop, shaded or line-art style, path guides, and orbit,
  pan (right-drag or Shift-drag), and zoom at any time.
  `animation.html#step=N` opens step N. `window.assemblyPlayer` exposes
  `play`, `pause`, `seek`, `gotoStep`, `state`, and `setStyle` for checks.

Limits: motions are straight translations, so screws do not spin. Flexible
parts (belts, cables, springs) are not modelled. The limit is 2000 instances.

## Extending

- CLI: `~/src/agents/bin/assembly-docs` (spec checks, clearance check, manual
  HTML). Manual style: `assets/web/manual.css`. Player page:
  `assets/web/animation.html`.
- Renderer and player: `assets/src/*.js`. Run `assets/src/build.sh` (bun) to
  rebuild the committed bundle `assets/web/app.js`.
- Tests: `python3 -m pytest -q tests/test_assembly_docs.py` in
  `~/src/agents`. After a change, also build, check, and publish
  `templates/example` and inspect the result.
